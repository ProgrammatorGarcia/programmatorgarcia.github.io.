Before you begin

Quick refresher: Revisit Loops Lab’s running total and input retry. Trace a total for input 4, then explain what happens if the first value entered is already valid. A counting loop has an endpoint. A retry loop checks the entry again after reading a replacement.

Day 1

Review input, loops, and decisions

Complete Activities 1 and 2, then start Activity 3.

Input validation · Running total

1. Sum of odd numbers

Ask for an integer n from 1 through 1000. If the entry is outside that range, print an error and ask again until it is valid. Then use a loop to add the odd numbers from 1 through 2 * n + 1, including both endpoints. Print the upper endpoint and the final sum.

Example run

Enter an integer from 1 through 1000:
0
That number is out of range. Try again:
3
The sum of the odd numbers from 1 through 7 is 16.

Build it in stages. First get the sum working with a valid entry. Start the total at zero and add each odd number inside the loop. Then add the retry loop before the summing loop.

Check. Try 1 for a sum of 4 and 1000 for 1002001. Try 0, then 1001, then 3 in one run. Only the last entry should be accepted.

Input validation · Divisibility · Boolean logic

2. Is it a leap year?

Ask for a positive integer year. If the entry is zero or negative, print an error and ask again until it is valid. A year divisible by 400 is a leap year. A year divisible by 100 but not 400 is not. For other years, divisibility by 4 decides. Print the year and whether it is a leap year.

Example run

Enter a positive integer year:
1900
The year 1900 is not a leap year.

Before you code. For each year below, decide which rule settles the question. You can express the rules with an if / else chain or a compound Boolean condition.

Check. 2023 and 1900 are not leap years. 2024 and 2000 are. Try 0 followed by 2024 to check the retry.

Divisibility · Loop bounds · Boolean state

3. Is it prime?

Read an integer and print whether it is prime. A prime is an integer greater than 1 whose only positive divisors are 1 and itself. Any input less than 2 is a valid entry and should be reported as not prime.

For numbers at least 2, use a loop to search for a divisor other than 1 or the number itself. A straightforward scan from 2 through the number minus 1 is enough. After the search, report the result once.

Example run

Enter an integer:
25
The number 25 is not prime.

Plan the search. What can you remember in a variable once you find a divisor? What should happen for 2, when the loop has no candidates to test?

Check. -3, 0, 1, and 25 are not prime. 2 and 29 are prime.

Input validation · Loop bounds · Updating two values

4. Find a Fibonacci term

Ask for a term number from 1 through 20. If the entry is outside that range, print an error and ask again. The first two terms are both 1. Each later term is the sum of the previous two, so the sequence begins 1, 1, 2, 3, 5, 8, 13, 21. Use a loop to compute the requested term and print its value.

Example run

Enter a term number from 1 through 20:
8
Term 8 is 21.

Trace it first. On paper, fill in the two previous terms and the new term for each row. When you update your variables, think about which old value you still need.

Capstone · Conditional update · Step counter

5. Follow the Collatz sequence

Ask for a starting integer from 1 through 100. For this activity, assume it is in range. Print Sequence: and the starting value on separate lines, then keep updating the current value until it reaches 1.

  • If the current value is even, divide it by 2.
  • If the current value is odd, multiply it by 3 and add 1.

Print each new value on its own line. Count one step for each update and report the total after reaching 1. Printing the starting value takes zero steps.

Example run

Enter a starting integer from 1 through 100:
5
Sequence:
5
16
8
4
2
1
Steps: 5

Plan the loop. Decide what you will print before, during, and after the loop. Where will the program check whether the current value is even?

Check. Start at 1 for zero steps, 2 for one step, and 7 for sixteen steps. Each sequence should end with 1.

Optional

Extension challenges

Choose an extension after completing the required activities.

Check for primes with fewer tests

Try a smaller upper limit for your divisor search. Explain why you can stop there, and compare how many tests the two versions make for 29 and 49.

Compare the ends of a word

Read one lowercase word with keyboard.next() and use a loop to determine whether it reads the same forward and backward. Use length() to find the word’s length and charAt(i) to read a character. The first position is 0 and the last is length() - 1.

Check. Try level, noon, java, and a.

Find a GCD, then an LCM

Read two positive integers from 1 through 100. Assume both are in range. First, use a loop to find the greatest common divisor, the largest positive integer that divides both inputs evenly. Then find the least common multiple, the smallest positive number that is a multiple of both inputs. Start by checking multiples of one input, or investigate how the two answers are related.

Check. 24 and 32 have GCD 8 and LCM 96. Also try equal inputs and two inputs that share no factor greater than 1.

Bonus challenge. After you have a working GCD solution, look up Euclid’s algorithm. Implement it and compare how many loop iterations the two approaches need for the same inputs.
